    MedGemma 빠른 참조 가이드¶

    🎯 한눈에 보는 MedGemma¶

    모델 선택 가이드¶

    ┌─────────────────────────────────────────────────────────────┐
│                    어떤 모델을 쓸까?                         │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   이미지 분석이 필요한가?                                    │
│        │                                                    │
│        ├── YES ──▶ MedGemma 4B (멀티모달)                   │
│        │              • X-ray, CT, 병리 슬라이드, 피부 사진   │
│        │              • 4090 (24GB)에서 추론 가능           │
│        │              • 파인튜닝: A100 권장                 │
│        │                                                    │
│        └── NO ───▶ MedGemma 27B (텍스트 전용)               │
│                       • 판독문, 임상 노트, EHR 데이터        │
│                       • 4090에서 추론 어려움 (A100 필요)     │
│                       • 복잡한 임상 추론에 유리              │
│                                                             │
└─────────────────────────────────────────────────────────────┘

    GPU 요구사항 (참고용)¶

    작업 4090 (24GB) 5090 (32GB) A100 (40/80GB)
    4B 추론 (int4) ✅ 가능 ✅ 가능 ✅ 가능
    4B 추론 (fp16) ⚠️ 한계 ✅ 가능 ✅ 가능
    4B 파인튜닝 (QLoRA) ⚠️ 한계 ⚠️ 한계 ✅ 가능
    27B 추론 (int4) ❌ 불가 ⚠️ 한계 ✅ 가능
    27B 파인튜닝 ❌ 불가 ❌ 불가 ✅ 80GB 필요

    🗺️ 기능 맵¶

    1. 이미지 → Context 생성¶

    ┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  의료 이미지  │────▶│   MedGemma   │────▶│   Context    │
│  (X-ray, CT) │     │     4B       │     │   Description│
└──────────────┘     └──────────────┘     └──────────────┘

    활용 예시: - 흉부 X-ray: "이 흉부 X-ray에서 관찰되는 주요 소견은?" - 병리 슬라이드: "이 조직 검체의 병리학적 특징 설명" - 시계열 비교: "두 X-ray 이미지의 차이점 분석"

    실습 노트북: - quick_start_with_hugging_face.ipynb - cxr_anatomy_localization_with_hugging_face.ipynb - cxr_longitudinal_comparison_with_hugging_face.ipynb

    2. 파인튜닝 (Fine-Tuning)¶

    ┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  기관 특화    │────▶│   QLoRA/     │────▶│  커스텀      │
│  의료 데이터  │     │   SFT        │     │  MedGemma    │
└──────────────┘     └──────────────┘     └──────────────┘

    지원 방식:

    방식 설명 GPU 요구사항
    SFT Supervised Fine-Tuning A100 40GB+
    QLoRA Quantized LoRA (효율적) A100 40GB+
    RLHF Reinforcement Learning A100 40GB+ (11시간 소요)

    언제 필요한가? - 특정 질환/기관에 특화된 성능 필요 시 - 고유한 이미징 프로토콜 적용 시 - 기관별 임상 워크플로우 맞춤 시

    실습 노트북: - fine_tune_with_hugging_face.ipynb - reinforcement_learning_with_hugging_face.ipynb

    3. 판독문 분석/비식별화¶

    ┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│   판독문     │────▶│  MedGemma    │────▶│  분석 결과   │
│   (텍스트)   │     │    27B       │     │  요약/평가   │
└──────────────┘     └──────────────┘     └──────────────┘

    활용 예시: - 요약: "이 판독문의 핵심 소견을 3줄로 요약해줘" - 평가: "이 판독문에 논리적 오류가 있는지 검토해줘" - 비식별화: "판독문에서 환자 식별 정보를 찾아 마스킹해줘" - 용어 설명: "이 판독문의 의학 용어를 환자용으로 쉽게 설명해줘"

    참고: 27B 모델은 텍스트 전용이지만, 더 긴 컨텍스트와 복잡한 추론 가능

    4. DICOM 통합¶

    ┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  DICOM Store │────▶│  MedGemma    │────▶│   분석 결과  │
│  /PACS/GCS   │     │  DICOM API   │     │              │
└──────────────┘     └──────────────┘     └──────────────┘

    입력 방식:

    방식 파라미터 사용 사례
    DICOM Store image_dicom PACS 연동, 표준 임상 시스템
    GCS URI image_gcs 클라우드 저장소 활용
    HTTP URL image_url 외부 이미지 접근
    Raw Bytes image_bytes 직접 파일 업로드

    3D 볼륨 처리 (CT/MRI): - 다중 슬라이스 자동 처리 - 슬라이스 인덱싱 및 정렬 - 볼륨 → 모델 입력 변환 파이프라인

    실습 노트북: - quick_start_with_dicom.ipynb - high_dimensional_ct_hugging_face.ipynb

    5. EHR Navigator (Agentic!)¶

    ┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  FHIR/EHR    │────▶│  Navigator   │────▶│  종합 리포트 │
│  환자 기록   │     │  Agent       │     │              │
└──────────────┘     └──────────────┘     └──────────────┘
                            │
                    ┌───────┴───────┐
                    │   Agentic     │
                    │   Workflow    │
                    │ • 탐색        │
                    │ • 계획        │
                    │ • 추론        │
                    │ • 종합        │
                    └───────────────┘

    Agentic 특징: - Intelligent Navigation: 관련 환자 정보 자동 식별 - Planning: 검색 전략 수립 - Synthesis: 복잡한 기록에서 핵심 정보 종합 - Long Context: 컨텍스트 윈도우 한계를 넘어서는 기록 처리

    활용 예시: - "이 환자의 지난 5년간 주요 입원 기록 요약" - "당뇨 관련 검사 결과만 추출해서 추이 분석" - "약물 복용 이력과 알레르기 정보 교차 확인"

    실습 노트북: - ehr_navigator_agent.ipynb

    📚 필수 배경지식¶

    1. SigLIP (Sigmoid Loss for Language-Image Pre-training)¶

    한 줄 설명: CLIP의 개선된 버전으로, 이미지-텍스트 매칭을 더 효율적으로 학습

    왜 중요한가? - MedGemma 4B의 이미지 인코더로 사용 - 의료 이미지에 특화된 사전 훈련 - X-ray, 병리, 피부과 등 다양한 모달리티 이해

    더 알아보기: - SigLIP Paper - CLIP vs SigLIP 비교

    2. QLoRA (Quantized Low-Rank Adaptation)¶

    한 줄 설명: 대규모 모델을 적은 메모리로 효율적으로 파인튜닝하는 기법

    작동 원리: 

    ┌─────────────────────────────────────────┐
│  기존 파인튜닝: 전체 파라미터 업데이트   │  → 메모리 많이 필요
├─────────────────────────────────────────┤
│  LoRA: 작은 adapter만 학습              │  → 메모리 절약
├─────────────────────────────────────────┤
│  QLoRA: 4bit 양자화 + LoRA              │  → 더 효율적
└─────────────────────────────────────────┘

    왜 중요한가? - A100 없이도 파인튜닝 가능성 (하지만 4090으로는 한계) - 기관 특화 모델을 효율적으로 만들 수 있음

    더 알아보기: - QLoRA Paper - Hugging Face PEFT 문서

    3. FHIR (Fast Healthcare Interoperability Resources)¶

    한 줄 설명: 의료 데이터 교환을 위한 표준 포맷

    데이터 구조 예시: 

    {
  "resourceType": "Patient",
  "id": "example",
  "name": [{"family": "Smith", "given": ["John"]}],
  "birthDate": "1970-01-01",
  "gender": "male"
}

    왜 중요한가? - EHR Navigator의 입력 포맷 - 대부분의 현대 EMR/EHR 시스템이 지원 - 구조화된 데이터로 AI 처리 용이

    더 알아보기: - FHIR 공식 문서 - Google Cloud Healthcare API

    4. DICOMweb¶

    한 줄 설명: DICOM 이미지를 웹 프로토콜로 접근하는 표준

    기본 개념: 

    DICOM (파일) → DICOMweb (HTTP/REST API) → 클라우드/애플리케이션

    주요 작업: - WADO-RS: 이미지 조회 - STOW-RS: 이미지 저장 - QIDO-RS: 이미지 검색

    왜 중요한가? - PACS 시스템과의 표준 연동 방식 - MedGemma DICOM 통합의 기반 - 클라우드 기반 의료 이미징의 표준

    더 알아보기: - DICOMweb 표준 - Google Cloud DICOM Store

    5. Reinforcement Learning from Human Feedback (RLHF)¶

    한 줄 설명: 사람의 피드백을 통해 모델을 개선하는 학습 방법

    프로세스: 

    1. 모델 응답 생성
2. 사람이 응답 평가 (좋음/나쁨)
3. 보상 모델 학습
4. 정책 최적화 (PPO/GRPO)

    MedGemma에서의 활용: - 의료 전문가의 피드백으로 모델 개선 - 임상적 정확성 향상 - reinforcement_learning_with_hugging_face.ipynb 참고

    더 알아보기: - RLHF Paper - GRPO (Group Relative Policy Optimization)
