    MedGemma 노트북 가이드¶

    📚 노트북 개요¶

    Google-Health/medgemma 리포지토리는 다양한 실습 노트북을 제공한다.

    🗂️ 노트북 목록¶

    노트북 용도 난이도 GPU 요구사항

    quick_start_with_model_garden.ipynb Vertex AI 배포 ⭐⭐ Vertex AI 리소스

    🚀 1. Quick Start with Hugging Face¶

    개요¶

    가장 기본적인 시작점. 텍스트 및 이미지 추론 방법 학습.

    주요 내용¶

    • 모델 로드 및 설정
    • 텍스트 생성
    • 이미지 + 텍스트 멀티모달 추론
    • 프롬프트 엔지니어링 기초

    실행 환경¶

    # 4090에서 실행 시 (int4 양자화)
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig

quantization_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.float16
)

model = AutoModelForCausalLM.from_pretrained(
    "google/medgemma-4b-it",
    quantization_config=quantization_config,
    device_map="auto"
)

    학습 포인트¶

    1. 모델 로딩: 양자화 설정에 따른 메모리 최적화
    2. 프롬프트 구조: 의료 이미지 분석을 위한 효과적인 프롬프트 작성
    3. 추론 파라미터: temperature, max_tokens 조정

    ☁️ 2. Quick Start with Model Garden¶

    개요¶

    Google Cloud Vertex AI Model Garden을 통한 배포.

    주요 내용¶

    • Vertex AI 프로젝트 설정
    • Model Garden에서 MedGemma 배포
    • 온라인/배치 추론
    • 엔드포인트 관리

    실행 환경¶

    # gcloud CLI 설정
gcloud config set project YOUR_PROJECT_ID

# Vertex AI Workbench에서 실행 권장

    학습 포인트¶

    1. 클라우드 배포: 관리형 서비스 활용
    2. 스케일링: 트래픽에 따른 오토스케일링
    3. 비용 최적화: 배치 처리 vs 온라인 추론

    🏥 3. Quick Start with DICOM¶

    개요¶

    DICOM 의료 영상 표준으로 직접 추론.

    주요 내용¶

    • DICOM 입력 방식 (Store, GCS, URL, Bytes)
    • 서버 사이드 전처리
    • PACS 통합 기초

    핵심 코드¶

    # DICOM Store 참조로 추론
dicom_input = {
    "image_dicom": {
        "dicomweb_uri": "https://healthcare.googleapis.com/v1/.../dicomWeb/studies/...",
        "instance_uid": "1.2.840.113619.2.55.3..."
    }
}

    학습 포인트¶

    1. DICOM 표준: DICOMweb 프로토콜 이해
    2. 입력 변환: 서버 측 자동 전처리
    3. 임상 통합: PACS 시스템 연동 준비

    🔧 4. Fine-tune with Hugging Face¶

    개요¶

    QLoRA/SFT를 통한 모델 커스터마이징.

    주요 내용¶

    • 데이터셋 준비 (NCT-CRC-HE-100K 예시)
    • QLoRA 설정
    • 훈련 루프 실행
    • 모델 저장 및 로드

    핵심 설정¶

    from peft import LoraConfig

lora_config = LoraConfig(
    r=16,  # LoRA rank
    lora_alpha=32,
    target_modules=["q_proj", "v_proj"],
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM"
)

    하드웨어 요구사항¶

    • 최소: A100 40GB
    • 권장: A100 80GB
    • 훈련 시간: 데이터셋 크기에 따라 다름 (10K 샘플 ≈ 2-4시간)

    학습 포인트¶

    1. 데이터 준비: 의료 이미지-텍스트 쌍 구성
    2. 파라미터 튜닝: learning rate, epochs, batch size
    3. 평가: 검증 데이터셋으로 성능 확인

    🎮 5. Reinforcement Learning¶

    개요¶

    RLHF/GRPO를 통한 고급 파인튜닝.

    주요 내용¶

    • 보상 모델 학습
    • PPO/GRPO 최적화
    • 인간 피드백 수집

    하드웨어 요구사항¶

    • 필수: A100 40GB+
    • 훈련 시간: ~11시간 (1700 steps)

    학습 포인트¶

    1. 보상 설계: 의료 도메인에 맞는 보상 함수
    2. 안정성: KL divergence 제약
    3. 평가: 전문가 평가 포함

    🫁 6. CXR Anatomy Localization¶

    개요¶

    흉부 X-ray에서 해부학적 구조 식별.

    주요 내용¶

    • 흉부 해부학 이해
    • 로컬라이제이션 기법
    • 시각화

    사용 사례¶

    입력: 흉부 X-ray 이미지
출력: 
  - 심장 윤곽 (Cardiac silhouette)
  - 폐야 (Lung fields)
  - 종격동 (Mediastinum)
  - 횡격막 (Diaphragm)
  - 쇄골 (Clavicles)

    학습 포인트¶

    1. 해부학적 지식: 의료 영상 분석 기초
    2. 로컬라이제이션: 관심 영역 식별
    3. 임상 활용: 진단 보조 도구 개발

    📊 7. CXR Longitudinal Comparison¶

    개요¶

    시계열 흉부 X-ray 비교 분석.

    주요 내용¶

    • 시계열 이미지 처리
    • 변화 감지
    • 질환 진행 모니터링

    사용 사례¶

    입력: 
  - 2024-01-01 흉부 X-ray
  - 2024-06-01 흉부 X-ray
출력:
  - "폐결절 크기가 5mm에서 8mm로 증가"
  - "새로운 침윤 소견 관찰"
  - "심비대 진행 없음"

    학습 포인트¶

    1. 시계열 분석: 변화 추적 방법
    2. 임상 의미: 질환 진행/호전 평가
    3. 자동화: 정기 검진 워크플로우

    📋 8. EHR Navigator Agent¶

    개요¶

    FHIR/EHR 데이터 탐색 에이전트.

    주요 내용¶

    • FHIR 리소스 이해
    • Agentic 탐색 로직
    • 정보 종합 및 요약

    핵심 기능¶

    # Agentic 쿼리 예시
query = """
환자의 당뇨 관리 상태를 평가해주세요:
1. 최근 HbA1c 추이
2. 약물 순응도
3. 합병증 발생 여부
"""

# Navigator가 자동으로:
# 1. Patient 리소스 조회
# 2. Observation에서 HbA1c 필터링
# 3. MedicationRequest에서 처방 확인
# 4. Condition에서 합병증 검색
# 5. 결과 종합

    학습 포인트¶

    1. FHIR 표준: 의료 데이터 교환 포맷
    2. 에이전트 설계: 자율적 탐색 로직
    3. 종합 능력: 복잡한 정보의 요약

    🧊 9. High-Dimensional CT¶

    개요¶

    3D CT 볼륨 데이터 처리.

    주요 내용¶

    • 다중 슬라이스 처리
    • 볼륨 전처리
    • 3D 특징 추출

    처리 파이프라인¶

    DICOM Volume (300+ slices)
    ↓
Parallel Slice Retrieval
    ↓
Slice Preprocessing (resize, normalize)
    ↓
Volume Assembly
    ↓
Model Input (selected slices or full volume)
    ↓
3D Analysis Result

    하드웨어 요구사항¶

    • 메모리: 대용량 볼륨 처리를 위해 높은 VRAM 필요
    • 저장소: CT 스터디당 100MB~1GB
    • 연산: 슬라이스 병렬 처리

    학습 포인트¶

    1. 3D 데이터 처리: 볼륨 데이터 다루기
    2. 메모리 관리: 대용량 데이터 효율적 처리
    3. 임상 적용: CT 판독 보조

    🔬 10. High-Dimensional Pathology¶

    개요¶

    전체 슬라이드 이미지(WSI) 병리 분석.

    주요 내용¶

    • WSI 패치 추출
    • 다중 패치 분석
    • 결과 집계

    처리 파이프라인¶

    Whole Slide Image (40,000 x 40,000 pixels)
    ↓
Patch Extraction (256 x 256 tiles)
    ↓
Parallel Patch Analysis
    ↓
Result Aggregation (Heatmap, Summary)
    ↓
Pathology Report

    사용 사례¶

    • 암 진단 (악성/양성 분류)
    • 조직 타이핑
    • Ki-67 양성률 계산 (우리 연구실 관련!)

    학습 포인트¶

    1. WSI 처리: 대용량 병리 이미지 다루기
    2. 패치 전략: 효율적인 분석을 위한 샘플링
    3. 결과 해석: 병리학적 의미 파악
