    실험 개요¶

    왜 이 실험을 했는가?¶

    MedGemma는 Google이 개발한 의료 특화 멀티모달 모델이다. 우리는 이 모델을 활용해서 방사선 판독문 생성 작업에 활용하고자 한다. 원본 모델도 이미 의료 도메인에 최적화되어 있지만, 우리 회사의 판독문 스타일과 용어에 맞게 파인튜닝이 필요하다.

    실험 흐름¶

    [1] 파인튜닝 (LoRA)
    ↓ 모델 성능 검증
[2] 로컬 서빙 테스트
    ↓ API 동작 확인
[3] 도커 이미지 빌드
    ↓
[4] 실제 서버 배포 (진행중)

    핵심 성과¶

    항목 결과
    파인튜닝 성능 ROUGE-L +9.72% 향상
    학습 시간 3.8초 (20샘플, 1에포크)
    로컬 서빙 Triton + vLLM + Gunicorn 구축 완료
    도커 이미지 빌드 완료, 서버 설치중

    Part 1: LoRA 파인튜닝¶

    1.1 작업 위치¶

    medgemma/challenge/
├── train.py              # 학습 스크립트
├── evaluation.py         # 평가 스크립트
├── requirements.txt      # 의존성
├── medgemma_lora_finetune_blog.md  # 상세 실험 기록
├── models/               # 다운로드한 모델
├── datasets/             # 학습 데이터
├── checkpoints/          # 체크포인트
└── outputs/              # 결과물

    1.2 LoRA가 뭔가?¶

    LoRA (Low-Rank Adaptation) 는 거대 언어 모델을 효율적으로 파인튜닝하는 기법이다.

    일반 파인튜닝:  모델 전체 (4.3B 파라미터) 학습 → 느리고 무거움
LoRA 파인튜닝:  작은 어댑터 (5.9M 파라미터)만 학습 → 빠르고 가벼움

    비유하자면: - 일반 파인튜닝 = 뇌 전체를 다시 교육 - LoRA = 필요한 지식만 추가로 주입하는 "특강"

    1.3 학습 설정¶

    # 사용한 설정
model_id = "google/medgemma-4b-it"   # 기본 모델

# LoRA 설정
lora_r = 8              # Rank (어댑터 크기)
lora_alpha = 16         # 스케일링 factor
lora_dropout = 0.05     # 드롭아웃
target_modules = ["q_proj", "k_proj", "v_proj", "o_proj"]  # 어텐션 레이어

# 학습 설정
epochs = 1
batch_size = 1
learning_rate = 2e-4
max_length = 256

    1.4 데이터셋¶

    ReXGradient-160K - 흉부 X-ray 판독문 데이터셋

    입력 (Findings):  "양측 폐에 공간 음영이 관찰됨..."
출력 (Impression): "양측 폐 침윤 소견은 폐렴과 일치함..."
    • 학습용: 20개 샘플 (최소 테스트)
    • 검증용: 5개 샘플
    • 평가용: 50개 샘플

    1.5 실행 방법¶

    cd /home/jkuhm/src/MoltsBot-Source/medgemma-clone/medgemma/challenge

# 1. 모델 & 데이터 다운로드 (최초 1회)
python train.py --download-model --download-dataset

# 2. 학습 실행
python train.py --train-size 20 --val-size 5 --epochs 1 --batch-size 1

# 3. 평가 실행
python evaluation.py --model-dir ./outputs --sample-size 50

    1.6 결과¶

    메트릭 기본 모델 LoRA 모델 향상률
    ROUGE-1 0.3116 0.3360 +7.83%
    ROUGE-2 0.1252 0.1304 +4.20%
    ROUGE-L 0.2805 0.3077 +9.72%
    BERTScore 0.8719 0.8797 +0.89%

    해석: - ROUGE-L이 가장 크게 향상됨 → 문장 수준 유사성 개선 - 20개 샘플만으로도 모든 메트릭 개선 - 3.8초 만에 학습 완료 (매우 효율적)

    1.7 개선된 예시¶

    입력 (Findings):

    "양측 폐에 흐린 공간 음영이 있음. 기흉이나 흉막 삼출의 증거 없음..."

    Ground Truth:

    "환자의 COVID-19 폐렴 병력과 일치하는 양측 폐 공간 음영"

    모델 생성 결과 ROUGE-L
    기본 "양측 폐 공간 음영... 기흉 없음..." 0.24
    LoRA "COVID-19 폐렴과 일치하는 양측 폐 공간 음영" 0.70

    Part 2: 로컬 서빙 구축¶

    2.1 작업 위치¶

    medgemma/python/serving/
├── local_serving.sh          # 로컬 서버 실행 스크립트 (메인)
├── LOCAL_SERVING_GUIDE.md    # 사용 가이드
├── simple_serving.py         # 간단 버전 (개발용)
├── predictor.py              # 추론 로직
├── Dockerfile                # 도커 이미지 빌드용
├── medgemma_docker_guide.md  # 도커 배포 가이드
└── ...

    2.2 서빙 아키텍처¶

    ┌─────────────────────────────────────┐
│  Docker Container (Triton)          │
│  - Port: 8500 (gRPC)                │
│  - Port: 8600 (HTTP)                │
│  - vLLM Backend                     │
│  - Model: medgemma-4b-it            │
└─────────────────────────────────────┘
        │ gRPC
        ▼
┌─────────────────────────────────────┐
│  Gunicorn + Flask (Host)            │
│  - Port: 8080                       │
│  - MedGemmaPredictor                │
│  - Vertex-style API                 │
└─────────────────────────────────────┘

    왜 이 구조인가? - Triton + vLLM: 고성능 추론, 배칭 지원 - Gunicorn + Flask: API 서버, Vertex AI 호환 - Docker로 격리: 환경 의존성 문제 해결

    2.3 실행 방법¶

    cd /home/jkuhm/src/MoltsBot-Source/medgemma-clone/medgemma/python/serving

# 서버 시작
./local_serving.sh start

# 상태 확인
./local_serving.sh status

# 테스트
./local_serving.sh test

# 서버 중지
./local_serving.sh stop

    2.4 API 사용 예시¶

    서버가 시작되면 http://localhost:8080 에서 API 사용 가능:

    # 헬스 체크
curl http://localhost:8080/health

# 텍스트 생성
curl -X POST http://localhost:8080/predict \
    -H "Content-Type: application/json" \
    -d '{
      "messages": [
        {"role": "user", "content": "Explain CT scans briefly."}
      ]
    }'

# OpenAI 호환 API
curl -X POST http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "messages": [
      {"role": "user", "content": "What is this image?"}
    ],
    "max_tokens": 150
  }'

    2.5 Simple Serving vs Local Serving¶

    항목 Simple Serving Local Serving (Triton)
    성능 낮음 (기본 Transformers) 높음 (vLLM 최적화)
    동시 요청 미지원 지원 (배칭)
    DICOM 처리 미지원 지원
    설정 복잡도 낮음 높음 (Docker 필요)
    용도 빠른 개발/테스트 프로덕션 테스트

    Part 3: 도커 배포¶

    3.1 왜 도커인가?¶

    로컬에서는 잘 돌아가지만, 실제 서버에 배포하려면: - GPU 드라이버, CUDA 버전, Python 패키지 등 환경이 다름 - 의존성 충돌 가능성 - 재현성 보장 어려움

    도커로 해결: - 모든 환경을 이미지로 패키징 - 어디서든 동일하게 실행 - 배포가 파일 복사 한 번으로 끝남

    3.2 배포 파이프라인¶

    [작업 PC]                              [배포 서버]
   │                                      │
   ├─ 1. docker build (이미지 생성)        │
   ├─ 2. docker save (tar 파일로 추출)     │
   ├─ 3. scp (파일 전송)  ─────────────────►│
   │                                      ├─ 4. docker load (이미지 로드)
   │                                      └─ 5. docker run (컨테이너 실행)

    3.3 실행 명령어¶

    # 1. 이미지 빌드
cd /home/jkuhm/src/MoltsBot-Source/medgemma-clone/medgemma
docker build -f python/serving/Dockerfile -t medgemma-serving:latest .

# 2. 이미지 추출 (tar 파일로)
docker save medgemma-serving:latest | gzip > medgemma-serving.tar.gz

# 3. 서버로 전송
scp medgemma-serving.tar.gz user@server:/path/to/

# 4. 서버에서 이미지 로드
docker load < medgemma-serving.tar.gz

# 5. 컨테이너 실행
docker run -d \
  --name medgemma-server \
  --gpus all \
  -p 8080:8080 \
  --shm-size=16g \
  medgemma-serving:latest

    3.4 주요 옵션 설명¶

    옵션 의미
    -d 백그라운드 실행
    --gpus all 컨테이너에 GPU 접근 권한 부여
    -p 8080:8080 포트 매핑 (호스트:컨테이너)
    --shm-size=16g 공유 메모리 확장 (AI 모델용)
