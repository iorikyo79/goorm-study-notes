    Medical Report Anonymization Deep-Dive¶

    Date: 2026-02-20 | Night Study Lab v2.0

    🎯 Executive Summary¶

    의료 보고서 비식별화(De-identification) 기술은 전통적인 Rule-based 접근법에서 최신 LLM 기반 방식까지 급격히 진화하고 있다. 본 연구에서는 HIPAA Safe Harbor, GDPR, 그리고 한국의 개인정보보호법(PIPA)을 기반으로 한 규제 프레임워크를 분석하고, Regex → NER/CRF → BERT → LLM으로 이어지는 기술적 진화를 체계적으로 정리한다. 특히 종적 데이터(longitudinal data)에서의 Date Shifting 알고리즘과 Privacy-Utility Trade-off 문제를 심층 분석하였다.

    1. 규제 프레임워크 및 표준¶

    1.1 HIPAA Safe Harbor (미국)¶

    HIPAA Privacy Rule은 의료 데이터 비식별화를 위한 두 가지 접근법을 제공한다:

    방식 설명
    Safe Harbor 18가지 식별자 제거 시 자동으로 비식별 데이터로 간주
    Expert Determination 전문가가 재식별 위험이 매우 낮음을 증명

    18 HIPAA PHI 식별자 (Complete List)¶

    1. Names - 환자, 가족, 고용주 이름
    2. Geographic Subdivisions - 주(State)보다 작은 지리적 단위 (주소, 우편번호 처음 3자리 제외)
    3. Dates - 연도 외 모든 날짜 (생년월일, 입퇴원일, 사망일 등)
    4. Phone Numbers - 전화번호
    5. Fax Numbers - 팩스번호
    6. Email Addresses - 이메일 주소
    7. Social Security Numbers - 주민등록번호/SSN
    8. Medical Record Numbers - 의무기록 번호
    9. Health Plan Beneficiary Numbers - 건강보험 수혜자 번호
    10. Account Numbers - 계좌번호
    11. Certificate/License Numbers - 자격증/면허 번호
    12. Vehicle Identifiers - 차량 번호 및 일련번호
    13. Device Identifiers - 의료기기 일련번호
    14. Web URLs - 웹사이트 URL
    15. IP Addresses - IP 주소
    16. Biometric Identifiers - 생체 인식 데이터 (지문, 홍채 등)
    17. Full-face Photographs - 얼굴 사진 및 비교 가능 이미지
    18. Any Other Unique Identifying Number - 기타 고유 식별번호

    중요: 나이의 경우 89세 이상은 모두 "90+"로 표기해야 함

    1.2 GDPR Pseudonymization (유럽)¶

    GDPR Article 4(5)는 Pseudonymization을 다음과 같이 정의한다:

    개인정보를 추가 정보 없이 특정 개인에게 귀속시킬 수 없는 방식으로 처리하되,
추가 정보는 별도로 보관하고 기술적/조직적 조치를 통해 귀속 방지

    핵심 차이점: - Pseudonymization: 여전히 개인정보로 간주 (GDPR 적용) - Anonymization: 완전히 비식별화되어 GDPR 범위 밖

    1.3 한국 개인정보보호법 (PIPA) 및 의료데이터 가이드라인¶

    2020년 PIPA 개정으로 가명정보(Pseudonymous Data) 개념이 도입되었다:

    법령 적용 범위 특징
    PIPA 일반 개인정보 가명처리 + 안전성 조치 시 통계/연구 목적 활용 가능
    Bioethics Act 생명윤리 연구 IRB 승인 필수
    Medical Service Act 의료 서비스 진료 목적 데이터 공유
    보건의료데이터 활용 가이드라인 의료 데이터 가명처리 구체적 방법 제시

    2024.12 개정 보건의료데이터 활용 가이드라인 주요 내용: - 가명정보 처리 절차 구체화 - 결합 정보 활용 방안 명시 - 데이터 활용 후 폐기/삭제 절차 보완

    2. 기술적 진화: Rule-based → Neural → LLM¶

    2.1 Rule-based (Regex) Approach¶

    대표 도구: PhysioNet deid, MITRE MIST

    # Example: Date Pattern Matching
DATE_PATTERNS = [
    r'\d{4}-\d{2}-\d{2}',           # YYYY-MM-DD
    r'\d{2}/\d{2}/\d{4}',           # MM/DD/YYYY
    r'(Jan|Feb|Mar|...)\s+\d{1,2}', # Month DD
]

    장점: - 해석 가능성 (Interpretability) - 패턴이 명확한 경우 높은 정확도 - 학습 데이터 불필요

    단점: - 변형/오타에 취약 - Out-of-vocabulary (OOV) 문제 - 컨텍스트 이해 불가

    성능: i2b2 벤치마크에서 약 75-85% F1-score

    2.2 Statistical/Neural NER (CRF, Bi-LSTM, BERT)¶

    진화 경로: 1. CRF (Conditional Random Fields) - 시퀀스 레이블링 2. Bi-LSTM-CRF - 장기 의존성 학습 3. BERT-based NER - 사전학습 언어모델 활용

    대표 모델 성능 (i2b2 2014 Dataset):

    Model Precision Recall F1-Score
    Regex-only 75% 94% 83%
    CRF 85% 89% 87%
    Bi-LSTM-CRF 89% 92% 90%
    BERT-NER 92% 94% 93%
    SciBERT-NER 94% 95% 94.5%

    한국어 모델: - KoBERT-NER: 한국어 임상 텍스트에 특화 - KoELECTRA: 한국어 EHR에 적용 가능

    2.3 LLM-based De-identification (Zero/Few-shot)¶

    DeID-GPT 연구 결과 (Huang et al., 2023):

    Model Setting Accuracy
    ChatGPT (GPT-3.5) Zero-shot 0.87
    GPT-4 Zero-shot >0.99
    GPT-4 Few-shot 0.99

    LLM 기반 접근의 장점: 1. Zero-shot 가능: 별도 학습 없이 PHI 탐지 2. 컨텍스트 이해: "Dr. Smith visited" vs "Smith is a common name" 3. 멀티링구얼: 영어 외 다국어 지원 4. 유연한 프롬프트 엔지니어링

    LLM 기반 접근의 단점: 1. Hallucination Risk: 존재하지 않는 PHI 생성 가능 2. 일관성 문제: 동일 입력에 다른 출력 3. 비용: 대규모 처리 시 API 비용 4. Privacy Concern: 클라우드로 데이터 전송

    최신 LLM-Anonymizer 성능 (NEJM AI, 2024): - GPT-4: 0.91 (implicit), 0.99 (explicit) 정확도 - Local LLM (온프레미스): 프라이버시 보장하며 유사 성능

    3. Date Shifting 알고리즘¶

    3.1 문제 정의¶

    종적 데이터(Longitudinal EHR)에서 날짜 정보는 필수적이지만, HIPAA Safe Harbor에 따라 연도 외 날짜는 제거해야 한다. 단순 제거는 시간적 순서 파괴 → 연구 가치 상실.

    3.2 SANT (Shift and Truncate) 알고리즘¶

    개발: El Emam et al., JAMIA 2016

    Algorithm: Shift and Truncate (SANT)
Input: Dataset D, Granularity m (default: 366 days)
Output: De-identified Dataset D'

1. For each patient p:
   - Assign random shift r ∈ {1, 2, ..., m}
   - Apply shift: date_new = date_original + r

2. Truncation:
   - Remove events with shifted date < (dataset_start + m)
   - Remove events with shifted date > (dataset_end - m)

3. Return D' with shifted dates

    핵심 원리: - 환자별 고유 시프트 → 생존분석, 시계열 분석 가능 - 양단 잘라내기(Truncation) → 경계 조건 공격 방어

    3.3 구현 시 고려사항¶

    class DateShifter:
    def __init__(self, granularity_days=366):
        self.granularity = granularity_days

    def shift_patient_dates(self, patient_records):
        # 환자별 고유 시프트 값
        shift = random.randint(1, self.granularity)

        for record in patient_records:
            record['shifted_date'] = record['date'] + timedelta(days=shift)

        return patient_records, shift

    def truncate_boundaries(self, dataset, start_date, end_date):
        # 양단 잘라내기
        buffer = timedelta(days=self.granularity)
        return [
            r for r in dataset 
            if (start_date + buffer) <= r['shifted_date'] <= (end_date - buffer)
        ]

    특수 케이스 처리: - 생년월일: 시프트 적용하되, 임상 사건과 일치 유지 - Mother-Child Link: 동일 시프트 값 사용 또는 링크 삭제 - Donor-Recipient: 동일 시프트 적용 필수

    4. Privacy-Utility Trade-off¶

    4.1 이론적 배경¶

    비식별화 강도 ↑ → 데이터 활용도 ↓

    대표 연구 (BMC Medical Informatics, 2024): - 19가지 비식별화 시나리오 적용 - 재식별 위험 감소 vs 예측 모델 성능 저하 - K=3 (한국 가이드라인 최소값)에서 최적 균형

    4.2 Privacy Models 비교¶

    Model 원리 장점 단점
    K-anonymity K개 이상 동일 레코드 단순, 직관 Homogeneity attack 취약
    L-diversity 민감값 L개 이상 다양성 Homogeneity 방어 Probabilistic inference
    T-closeness 민감값 분포 유지 분포 기반 공격 방어 구현 복잡
    Differential Privacy 노이즈 추가 수학적 보장 데이터 왜곡

    4.3 Adversarial Re-identification Attacks¶

    1. Linkage Attack: 외부 데이터와 결합
    2. Homogeneity Attack: 동일 그룹 내 민감정보 추론
    3. Composition Attack: 여러 비식별 데이터셋 결합
    4. Background Knowledge Attack: 사전 지식 활용

    방어 전략: - K ≥ 5 권장 (연구 목적) - Quasi-identifier 일반화 수준 조정 - Differential Privacy 노이즈 캘리브레이션
