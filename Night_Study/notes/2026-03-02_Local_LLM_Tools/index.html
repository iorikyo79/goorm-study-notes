    로컬 LLM 실행 도구 종합 조사 보고서¶

    조사 일시: 2026년 3월 2일 목적: Qwen3.5 모델 로컬 실행을 위한 최적 도구 선택

    1. 핵심 요약¶

    llama.cpp가 뭔가요? 🤔¶

    llama.cpp는 "엔진"이자 "라이브러리"입니다.

    • C/C++로 작성된 LLM 추론 엔진 (Georgi Gerganov 개발)
    • GGUF 파일 포맷으로 모델을 실행
    • 외부 의존성 없이 다양한 하드웨어 지원 (CPU, GPU, NPU)
    • Ollama, LM Studio, GPT4All, llamafile 등이 모두 llama.cpp를 백엔드로 사용

    관계도¶

    ┌─────────────────────────────────────────────────┐
│                   llama.cpp                      │
│              (C++ 추론 엔진/라이브러리)            │
│                                                   │
│  ┌─────────┐  ┌──────────┐  ┌────────────────┐  │
│  │ Ollama  │  │ LM Studio│  │ GPT4All, etc.  │  │
│  │ (CLI)   │  │ (GUI)    │  │                │  │
│  └─────────┘  └──────────┘  └────────────────┘  │
│                                                   │
│  ▲ 편의성 계층 (llama.cpp를 내부적으로 사용)      │
└─────────────────────────────────────────────────┘

    핵심 이해: Ollama와 LM Studio는 llama.cpp를 "포장"해서 사용하기 쉽게 만든 것입니다. 직접 llama.cpp를 쓰면 더 많은 제어권을 가집니다.

    2. 도구별 상세 비교¶

    2.1 llama.cpp (엔진)¶

    항목 내용
    정체 C/C++로 작성된 LLM 추론 라이브러리
    특징 외부 의존성 없음, 최소 설치 (90MB)
    지원 하드웨어 CPU (AVX/AVX2/AVX512), NVIDIA GPU (CUDA), AMD GPU (HIP/Vulkan), Apple Silicon (Metal), Intel GPU (SYCL)
    난이도 ⭐⭐⭐⭐⭐ (높음 - 컴파일/CLI 필수)
    제어권 완전한 제어 (모든 파라미터 조정 가능)

    장점: - 최고의 성능 (직접 컴파일 시 하드웨어 최적화) - 최소 메모리/디스크 사용 - 서버 모드로 API 제공 가능 (llama-server) - Vulkan 백엔드로 AMD GPU도 완벽 지원

    단점: - CLI 기반, 학습 곡선 높음 - 모델 직접 다운로드 필요 - 설정이 복잡할 수 있음

    사용법 예시: 

    # 직접 실행
llama-cli -m Qwen3-8B-Q4_K_M.gguf --interactive

# 서버 모드 (API + 웹 UI)
llama-server -m Qwen3-8B-Q4_K_M.gguf --port 8080

# Hugging Face에서 직접 다운로드 후 실행
llama-server -hf ggml-org/gemma-3-1b-it-GGUF

    2.2 Ollama (CLI 래퍼)¶

    항목 내용
    정체 llama.cpp 기반의 CLI 도구
    특징 백그라운드 서버 + 간편 CLI
    설치 크기 ~4.6GB (모든 라이브러리 포함)
    난이도 ⭐⭐ (낮음 - 설치 후 바로 사용)
    제어권 중간 (기본 설정은 자동, 커스텀 가능)

    장점: - 설치 즉시 사용 가능 - ollama run qwen3 한 줄로 모델 실행 - 자체 모델 라이브러리 - OpenAI 호환 API 기본 제공 - Modelfile로 커스텀 모델 생성 가능

    단점: - llama.cpp 대비 약간의 성능 손실 - AMD GPU의 경우 Vulkan 지원이 기본이 아님 (컴파일 필요) - 설치 크기가 큼

    사용법 예시: 

    # 모델 다운로드
ollama pull qwen3:8b

# 실행
ollama run qwen3:8b

# API 서버 (기본 localhost:11434)
curl http://localhost:11434/api/generate -d '{"model": "qwen3:8b", "prompt": "안녕"}'

    2.3 LM Studio (GUI 래퍼)¶

    항목 내용
    정체 llama.cpp 기반의 GUI 애플리케이션
    특징 Electron 기반, Hugging Face 통합
    설치 크기 ~528MB
    난이도 ⭐ (최저 - GUI로 모든 것 해결)
    제어권 낮음 (자동 설정, 일부 조정 가능)

    장점: - 가장 사용자 친화적 - Hugging Face 모델 브라우저 내장 - 채팅 UI 기본 제공 - CLI도 제공 (lms)

    단점: - Electron 앱으로 리소스 사용량 높음 - Windows에서 작업 표시줄 문제 보고됨 - CLI가 기능 제한적 - 성능 오버헤드 존재

    사용법: - GUI로 검색 → 다운로드 → 채팅 - CLI: lms load <model> → lms chat

    2.4 성능 비교 요약¶

    벤치마크 조건 llama.cpp Ollama LM Studio
    Apple M1 Pro 16.5 t/s 0.22 t/s* -
    일반 GPU 161 t/s 89 t/s -
    Mac Studio M3 Ultra (Gemma 3 1B) - 149 t/s 237 t/s
    Mac Studio M3 Ultra (27B 모델) - 24 t/s 33 t/s

    *Ollama가 GPU를 제대로 활용하지 못한 경우

    결론: 직접 컴파일한 llama.cpp가 최고 성능, Ollama와 LM Studio는 비슷하거나 상황에 따라 다름

    3. GGUF 파일 포맷과 양자화¶

    3.1 GGUF란?¶

    GGUF (GPT-Generated Unified Format): - 모델 가중치 + 하이퍼파라미터 + 토크나이저를 하나의 파일에 저장 - 메모리 매핑(mmap) 지원 → 빠른 로딩 - llama.cpp 생태계의 표준 포맷

    3.2 양자화(Quantization)란?¶

    FP16/FP32 → INT8/INT4/INT2로 변환하여: - 모델 크기 감소 (70% 이상) - 메모리 사용량 감소 - 추론 속도 향상 - 품질 손실 최소화

    3.3 양자화 포맷 상세¶

    Legacy 포맷 (구형)¶

    포맷 크기 (7B) Perplexity 증가 특징
    Q4_0 3.50GB +0.2499 단일 스케일, 빠름 but 품질 손실 큼
    Q4_1 3.90GB +0.1846 스케일 + 오프셋, 약간 개선
    Q5_0 4.30GB +0.0796 5비트, 균형
    Q8_0 7.50GB ~0 FP16에 거의 근접

    K-Quants (현대형, 추천) ⭐¶

    포맷 크기 (7B) 특징 추천 상황
    Q4_K_S ~3.5GB 거의 모든 것을 4비트로 최소 크기
    Q4_K_M ~4.0GB 중요 레이어는 5-6비트 안전한 기본값
    Q4_K_L ~4.3GB 더 많은 레이어 고비트 품질 우선
    Q5_K_M ~5.0GB 5비트 기반, 중요 부분 6비트 품질/크기 균형
    Q6_K ~6.0GB 거의 무손실 고사양

    I-Quants (최신, 고효율)¶

    포맷 특징 장단점
    IQ4_XS ~4.25 bpw Q4_K_M보다 작고 비슷한 품질, 하지만 처리 속도 느릴 수 있음
    IQ3_XS/M 3비트급 매우 작은 크기, 품질 민감

    3.4 양자화 선택 가이드¶

    기본 원칙: - Q4_K_M: 안전한 기본값 (대부분의 상황) - Q5_K_M: 품질이 중요하고 메모리 여유 있을 때 - Q8_0: 최고 품질 필요, 메모리 충분할 때

    메모리 기준 (7B 모델): | RAM/VRAM | 추천 양자화 | |----------|-------------| | 4-6 GB | Q4_K_S 또는 더 작은 모델 | | 8 GB | Q4_K_M | | 12-16 GB | Q5_K_M | | 24 GB+ | Q6_K 또는 Q8_0 |

    4. H/W 제약 상황별 추천¶

    4.1 사용자 환경 고려사항¶

    집사의 상황: - Qwen3.5 모델 실행 목표 - H/W 제약 존재 (구체적 사양 확인 필요) - 로컬 PC에서 테스트

    4.2 Qwen3.5 모델별 요구사항 (추정)¶

    모델 Q4_K_M 크기 최소 RAM 권장 RAM
    Qwen3.5-3B ~2.0 GB 4 GB 6 GB
    Qwen3.5-7B ~4.5 GB 8 GB 12 GB
    Qwen3.5-14B ~9.0 GB 16 GB 24 GB
    Qwen3.5-32B ~20 GB 32 GB 48 GB

    4.3 도구 선택 가이드¶

    상황별 추천:

    상황 추천 도구 이유
    처음 시작 Ollama 설치 간편, 바로 사용
    AMD GPU (Windows) llama.cpp (Vulkan) Ollama/LM Studio의 AMD 지원 불완전
    최고 성능 필요 llama.cpp (직접 컴파일) 하드웨어 최적화
    GUI 선호 LM Studio 시각적 인터페이스
    API 서버 구축 Ollama 또는 llama.cpp server OpenAI 호환 API

    5. 시작점 및 주의사항¶

    5.1 시작 전 체크리스트¶

    1. GPU 확인
    2. NVIDIA: CUDA 지원 (모든 도구 OK)
    3. AMD: Vulkan 또는 ROCm 필요 (llama.cpp 권장)
    4. Intel: SYCL 지원 (llama.cpp)

    5. 없음: CPU 모드 (모든 도구 OK, 느림)

    6. 메모리 확인

    7. 시스템 RAM vs GPU VRAM 구분

    8. 모델 크기 + 컨텍스트 + OS 오버헤드 고려

    9. OS 확인

    10. Linux: 모든 기능 지원
    11. macOS (Apple Silicon): Metal 지원, 최고의 효율
    12. Windows: CUDA/Vulkan 지원, ROCm 미지원

    5.2 일반적인 실수¶

    ❌ Q8이 Q4보다 "더 좋다"고 생각함 - Q8은 더 크고 느릴 뿐, 항상 더 좋은 것은 아님 - Q4_K_M으로 충분한 품질

    ❌ VRAM만 보고 RAM 무시 - CPU offloading 시 시스템 RAM도 중요 - 컨텍스트 길이에 따라 추가 메모리 필요

    ❌ 양자화 없이 원본 모델 다운로드 - FP16 모델은 2-4배 더 큼 - GGUF 변환 필요

    5.3 추천 시작 경로¶

    Step 1: Ollama로 빠르게 테스트 

    # 설치
curl -fsSL https://ollama.com/install.sh | sh

# Qwen3.5 실행
ollama run qwen3.5:7b

    Step 2: H/W 제약 확인 후 양자화 레벨 조정 - VRAM 부족 → Q4_K_S 또는 더 작은 모델 - 품질 부족 → Q5_K_M 또는 Q6_K

    Step 3: (선택) llama.cpp로 마이그레이션 - 더 많은 제어권 필요 시 - AMD GPU 사용 시 - 최고 성능 필요 시

    6. 파일 확장자 정리¶

    확장자 설명 사용 도구
    .gguf GGUF 포맷 (표준) llama.cpp, Ollama, LM Studio
    .ggml 구형 포맷 (deprecated) 사용 비권장
    .safetensors Hugging Face 표준 transformers, vLLM
    .bin PyTorch 바이너리 transformers
    .onnx ONNX 포맷 ONNX Runtime
    .exl2 EXL2 양자화 ExLlamaV2

    변환: Hugging Face 모델 → convert-hf-to-gguf.py → GGUF

    7. 결론 및 추천¶

    집사를 위한 추천 🐱¶

    1단계 (빠른 테스트): 

    # Ollama 설치 후
ollama run qwen3.5:7b-q4_K_M

    2단계 (H/W 제약 시): - VRAM 8GB 미만: Qwen3.5-3B Q4_K_M - VRAM 8-12GB: Qwen3.5-7B Q4_K_M - VRAM 16GB+: Qwen3.5-7B Q5_K_M 또는 Qwen3.5-14B Q4_K_M

    3단계 (심화): - llama.cpp 직접 사용으로 최적화 - Vulkan 백엔드로 AMD GPU 활용 - CPU offloading 전략 수립
