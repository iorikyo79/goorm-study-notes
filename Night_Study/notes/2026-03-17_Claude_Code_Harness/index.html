    Claude Code Harness 분석 및 Medical Report Converter 적용¶

    개요¶

    Claude Code Harness 프레임워크를 심층 분석하고, 이를 Medical Report Converter 프로젝트에 적용하여 LLM Code Agent의 출력 품질을 60% 향상시키는 방법을 연구했습니다.

    연구 배경¶

    문제 정의¶

    LLM Code Agent (Claude Code 등)는 자연어로부터 기능적인 소프트웨어를 생성할 수 있지만, 다음과 같은 구조적 한계가 있습니다:

    1. Architecture - 모놀리스 단일 파일 구현, 모듈화 부족
    2. Test Coverage - 명시적 지시 없이는 테스트를 거의 생성하지 않음
    3. Error Handling - Happy Path에 집중, Edge Case 커버리지 부족

    Harness의 해결책¶

    Harness는 에이전트가 한 줄의 코드를 작성하기 전에, 경험 많은 엔지니어가 프로젝트에 가져오는 것과 동일한 종류의 구조적 컨텍스트를 제공합니다.

    연구 방법론¶

    분석 대상¶

    • GitHub Repository: revfactory/claude-code-harness
    • 논문: "Harness: Structured Pre-Configuration for Enhancing LLM Code Agent Output Quality" (Hwang, M. 2026)
    • 실험 결과: 15개 소프트웨어 엔지니어링 과제 (Basic 5, Advanced 5, Expert 5)

    분석 항목¶

    1. Harness 구조: CLAUDE.md, Skills, Agents, Commands
    2. 실험 결과: A/B 테스트 (Baseline vs Harness)
    3. 실제 적용: Medical Report Converter PRD에 적용

    핵심 발견¶

    1. 압도적 품질 향상¶

    Metric Baseline Harness Delta
    평균 점수 49.5 79.3 +29.9 (+60%)
    승률 — — 15/15 (100%)
    표준편차 5.3 3.6 -32% variance

    2. 복잡도-효과 상관관계¶

    난이도가 높을수록 Harness의 효과가 증폭됩니다:

    • Basic: +23.8점
    • Advanced: +29.6점
    • Expert: +36.2점

    Delta가 Basic에서 Expert까지 52% 증가 — Harness는 가장 필요한 곳에서 가장 큰 가치를 제공합니다.

    3. 차원별 분석 (Top 4)¶

    1. Test Coverage (+4.9) — Baseline 평균 2.5점 (거의 테스트 없음)
    2. Architecture (+4.4) — Baseline 평균 3.9점 (모놀리스 성향)
    3. Error Handling (+3.0)
    4. Extensibility (+3.0)

    Medical Report Converter 적용¶

    프로젝트 개요¶

    • 목표: 판독문 이미지를 HTML로 자동 변환하는 시스템
    • 핵심 요구사항: 100% 정확성, Human-in-the-Loop 검수
    • PRD 위치: /home/jkuhm/clawd/projects/medical-report-converter/PRD.md

    Harness 구성¶

    Medical Report Converter를 위해 다음 Harness를 구성했습니다:

    medical-report-converter-harness/
└── .claude/
    ├── CLAUDE.md                    # 5단계 파이프라인 아키텍처
    ├── skills/
    │   ├── pdf-parsing/SKILL.md     # PDF 파싱
    │   ├── ocr-processing/SKILL.md  # OCR 처리
    │   └── medical-terminology/SKILL.md  # 의료 용어
    ├── agents/
    │   ├── parser.md                # PDF/이미지 파싱
    │   ├── ocr-integrator.md        # OCR 통합
    │   ├── extractor.md             # 데이터 추출
    │   ├── converter.md             # HTML 변환
    │   ├── validator.md             # 검증
    │   └── tester.md                # 테스트
    └── commands/
        ├── convert.md               # /convert
        └── validate.md              # /validate

    Harness 구성 (완전한 구현)¶

    • CLAUDE.md: 5단계 파이프라인 (Input → Image Analysis → Human Review → HTML Generation → Output)
    • 3개 Skills: PDF Parsing, OCR Processing, Medical Terminology
    • 6개 Agents: Parser → OCR Integrator → Extractor → Converter → Validator → Tester
    • 2개 Commands: /convert, /validate

    결론¶

    핵심 인사이트¶

    1. 구조가 능력을 결정한다 — LLM의 지식은 충분합니다. 부족한 것은 프로젝트별 구조적 가이드입니다.
    2. 테스트 커버리지가 가장 크게 개선됨 (+4.9) — 가이드 없는 에이전트는 거의 테스트를 작성하지 않습니다.
    3. 복잡도가 효과를 증폭시킴 — 단순한 과제는 적당한 개선, 복잡한 시스템은 극적인 향상.
    4. 자동 생성이 가능 — Harness meta-skill이 자연어 설명으로부터 구성을 자동 생성할 수 있습니다.
