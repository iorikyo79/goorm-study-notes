    03. ONNX Runtime (ORT) & Execution Providers¶

    변환된 .onnx 파일은 그 자체로는 아무것도 하지 못합니다. 이를 읽어서 연산을 수행하는 엔진이 바로 ONNX Runtime (ORT)입니다.

    1. ORT의 역할¶

    ONNX Runtime은 단순한 '실행기'가 아니라 '최적화 컴파일러'에 가깝습니다. 1. 그래프 최적화: 불필요한 노드를 제거하거나 합칩니다. (예: Conv + BatchNormalization → Conv 하나로 융합) 2. 하드웨어 매핑: CPU, GPU, NPU 등 각 하드웨어에 맞는 최적의 커널(Kernel)을 연결합니다.

    2. Execution Providers (EP)¶

    ORT의 가장 강력한 특징입니다. 코드를 바꾸지 않고 설정 한 줄만 바꾸면 실행 하드웨어를 교체할 수 있습니다.

    주요 Providers¶

    • CPUExecutionProvider: 기본값. 모든 환경에서 돌아가지만 느림. (AVX, AVX512 등 명령어셋 활용)
    • CUDAExecutionProvider: NVIDIA GPU 가속. (가장 대중적)
    • TensorrtExecutionProvider: NVIDIA TensorRT 엔진을 활용한 초고속 추론.
    • CoreMLExecutionProvider: Apple(macOS/iOS) 기기용. (M1/M2 칩 가속)

    사용 코드¶

    import onnxruntime as ort

# 사용 가능한 하드웨어 리스트 확인
print(ort.get_available_providers())
# 출력 예: ['CUDAExecutionProvider', 'CPUExecutionProvider']

# 세션 생성 (우선순위 순서대로)
session = ort.InferenceSession(
    "model.onnx", 
    providers=['CUDAExecutionProvider', 'CPUExecutionProvider']
)

# 만약 CUDA가 설치되어 있다면 GPU로, 없으면 CPU로 자동 백업됩니다.

    3. 추론 실행 (Inference)¶

    ORT는 NumPy 배열을 입출력으로 사용합니다. (PyTorch Tensor가 아님에 주의!)

    import numpy as np

# 1. 입력 데이터 준비 (NumPy)
# 모델 변환 시 지정한 input_names와 정확히 일치해야 함
input_data = {
    "input": np.random.randn(1, 3, 224, 224).astype(np.float32)
}

# 2. 실행
# None은 모든 출력을 다 받겠다는 의미
outputs = session.run(None, input_data)

# 3. 결과 확인
print(outputs[0].shape)

    4. IO Binding (고급 최적화)¶

    기본적으로 session.run()은 데이터를 CPU 메모리 ↔ GPU 메모리로 복사하는 과정이 포함됩니다. 이 복사 비용조차 아까운 초고성능 환경에서는 IO Binding을 사용해 데이터를 GPU에 미리 올려두고 복사 없이 연산만 수행할 수 있습니다. (주로 영상 처리 파이프라인에서 사용)
