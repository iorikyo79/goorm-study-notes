    04. 최적화의 꽃: 양자화 (Optimization & Quantization)¶

    모델을 ONNX로 바꾸기만 해도 빨라지지만, "양자화(Quantization)"를 적용하면 드라마틱한 성능 향상(2~4배)과 용량 감소(1/4)를 얻을 수 있습니다.

    1. 양자화란? (What is Quantization?)¶

    딥러닝 모델은 기본적으로 32비트 부동소수점 (FP32) 숫자로 이루어져 있습니다. 이를 8비트 정수 (INT8) 등으로 표현 단위를 낮추는 기술입니다.

    • FP32 (4 Byte): 0.123456789... (정밀함, 무거움)
    • INT8 (1 Byte): -128 ~ 127 (덜 정밀함, 가벼움)

    왜 빨라지는가?¶

    1. 메모리 대역폭 절약: 데이터를 1/4만 읽어도 되므로, 메모리 병목(Memory Bound)이 심한 최신 LLM/Transformer 모델에서 효과가 큽니다.
    2. 연산 속도: CPU/GPU는 INT8 연산을 FP32보다 훨씬 빠르게(Vectorized) 처리합니다.

    2. 양자화의 종류¶

    2.1 Dynamic Quantization (동적 양자화) - 가장 추천¶

    • 방식: 가중치(Weight)는 미리 INT8로 바꿔두고, 입력 데이터(Activation)는 실행되는 순간(Runtime)에 통계를 내서 INT8로 바꿉니다.
    • 대상: BERT, LSTM, Transformer 계열 (파라미터가 많은 모델).
    • 장점: 별도의 보정 데이터(Calibration Data)가 필요 없고 사용이 매우 쉽습니다.

    2.2 Static Quantization (정적 양자화)¶

    • 방식: 가중치와 입력 데이터 모두 미리 범위를 계산해서 고정시킵니다.
    • 대상: CNN (이미지 처리) 모델.
    • 단점: 실제 데이터(Calibration Data)를 미리 조금 돌려보면서 범위를 측정하는 과정이 필요합니다.

    3. 실습 코드: GLiNER 모델 양자화하기¶

    onnxruntime.quantization 패키지를 사용하면 코드 몇 줄로 끝납니다.

    from onnxruntime.quantization import quantize_dynamic, QuantType

model_fp32 = "model.onnx"
model_int8 = "model_quantized.onnx"

# 동적 양자화 실행
quantize_dynamic(
    model_input=model_fp32,
    model_output=model_int8,
    weight_type=QuantType.QUInt8,  # 가중치를 Unsigned INT8로 변환
    optimize_model=True            # 변환 전 그래프 최적화(Fusion) 수행
)

print(f"양자화 완료! {model_int8}")

    결과 비교 (예시)¶

    • 용량: 500MB → 130MB (약 1/4 감소)
    • 속도: CPU 기준 약 2~3배 향상
    • 정확도: FP32 대비 약 99% 수준 유지 (거의 차이 없음)

    4. Graph Optimization (그래프 최적화)¶

    양자화 전에 수행되는 필수 과정입니다. * Constant Folding: 상수끼리의 연산(1 + 2)은 미리 계산해서 3으로 바꿔둡니다. * Operator Fusion: Conv -> Relu 처럼 자주 붙어 다니는 연산을 ConvRelu라는 하나의 커널로 합쳐서 메모리 접근 횟수를 줄입니다.
